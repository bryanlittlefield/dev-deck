Dev Deck

A developer profile for the Womier DUO87’s touch screen: live Claude Code status you can read at a glance, one-tap prompts and permission answers, AI-written git commits, a wide git display, and VS Code and git keys. This guide covers installing it, using it, and changing it.

What’s installed

Everything lives in ~/.duo87, a clone of the repo, except the pieces that have to sit inside other apps. duo87 install backs up every file it changes to ~/.duo87/backups/ first.

Claude Codehooks →~/.duo87/state→Dev Deck plugin→touch screentap →VS Code / Claude
Dev Deck plugin
Runs inside the Play Deck app on its bundled Node 20. It draws the live keys, including the wide git display across a row, and does the work when you tap them.~/Library/Application Support/HotSpot/StreamDock/plugins/com.duo87.devdeck.sdPlugin
Dev profile
Three pages (Claude, Git, VS Code), set as the active profile. An importable copy doubles as a backup.~/.duo87/profile/Dev Deck.streamDockProfile
Claude Code hook
One async hook on 11 events writes each session’s state (prompt, tool, pending approval, last reply). It never blocks Claude, and your existing notifier hooks are untouched.~/.claude/settings.json → ~/.duo87/bin/claude-status-hook.js
smart-commit
Stages, has Claude Haiku write the message, lets you confirm, commits (signed and signed-off), optionally pushes.~/.duo87/bin/smart-commit · settings in ~/.duo87/config.json
VS Code wiring
16 keybindings on unused F16–F19 combos and 5 user tasks the touch keys trigger. Nothing else in VS Code is changed.~/Library/Application Support/Code/User/keybindings.json and tasks.json
Remote bridge
A small VS Code extension that runs on your Mac. In Remote-SSH, Codespaces and container windows it copies the remote Claude state to your Mac over VS Code’s own connection, so remote sessions show up on the deck.duo87.devdeck-bridge · source in ~/.duo87/vscode-bridge
Remote kit
The hook and smart-commit, packaged for SSH hosts and codespaces. You install it per machine; nothing is installed remotely until you do.duo87 remote <host> · duo87 codespace <name> · duo87 kit
duo87-keys
A tiny native helper (Swift source included) that brings an app forward, presses shortcuts, and pastes prompts while keeping your clipboard intact.~/.duo87/bin/duo87-keys · ~/.duo87/src/duo87-keys.swift
duo87 tool
Rebuilds and reinstalls everything from layout.json, checks health, shows what the deck sees.~/.duo87/bin/duo87 install | doctor | status | guide

Walkthrough

Tick each step off as you go; the checkmarks are remembered in this browser.

1

Install

You need a Mac with the DUO87 Play Deck app, Node.js 18 or newer (with npm), the Xcode Command Line Tools (xcode-select --install), and VS Code with the Claude Code extension. The Claude Code CLI writes commit messages; without it you get a basic message to edit. ImageMagick (crisper default images) and gh (the PR keys) are optional.

git clone https://github.com/bryanlittlefield/dev-deck.git ~/.duo87
~/.duo87/bin/duo87 install

It has to live in ~/.duo87: the plugin, the Claude hook and the VS Code tasks look for it there. install builds the key images and the Dev profile, copies the plugin into the Play Deck app and makes the profile active, adds the VS Code keybindings and tasks, registers the Claude Code hook, installs the bridge extension, and restarts the Play Deck app. Every file it changes is backed up to ~/.duo87/backups/ first.

To update: git -C ~/.duo87 pull && ~/.duo87/bin/duo87 install. Then run duo87 doctor to check every piece.

2

Check the hardware

  • Seat the screen module on the magnetic contacts where the Ins/Home/PgUp cluster sits. Those nav keys still exist on the Play Deck’s built-in Keyboard profile if you need them.
  • Put the keyboard in Mac mode: press Fn+Z (the Z key flashes white). Fn+X switches back to Windows mode.
  • Plug it straight into the Mac with the USB-C cable that came with it. Hubs are the usual cause of the screen disconnecting.

Good to know: in Mac mode the top row is media keys, and Fn+F1–F12 gives real F-keys. The touch keys send real key codes, so they work either way.

3

Confirm macOS permissions

  • Accessibility: turn it on for DUO87_Play_Deck under System Settings → Privacy & Security → Accessibility. It’s what lets the keys press shortcuts. duo87 install and duo87 doctor tell you if it’s missing.
  • Automation → System Events: Womier’s own Hotkey and Text actions need this. If macOS asks, allow it. The Dev Deck keys don’t need it.
  • Notifications: smart-commit posts a notification when it finishes. They appear under Script Editor in Notification settings, so allow that if you want them.

After changing a permission, quit the Play Deck app from its menu-bar icon and open it again.

4

Open the app and find your pages

After installing, the Dev Deck profile is active and the screen should look like the preview at the top of this page.

  • The screen is 3 keys wide and 4 tall. The preview above matches it key for key.
  • Moving between pages: the bottom-right key goes to the next page, and on the last page it goes back to the first. If you reorder pages in the app, run duo87 install afterwards so those keys follow your new order.
  • Other profiles (Keyboard, Touchbar, Scenes 1) are a click away in the app window.
  • The app window opens from the menu-bar icon. Click any key to see its settings on the right; Dev Deck keys have their own fields (label, prompt, shortcut, icon, color).

If a key looks blank or black, see Keys are blank in Troubleshooting. It’s a one-line setting.

5

Drive Claude Code from the deck

The Claude page is built around Claude Code in the VS Code sidebar. The top row is what Claude is doing, with Allow and Deny right beside it. The second row is your last prompt, Focus and New Chat. The bottom two rows hold saved prompts, Smart Commit and the page key.

  • Claude status (top-left) updates live from every session: Working with the tool and a timer, amber Approve? with what Claude wants to run, Question, green Done, or red Error. A number badge means several sessions are busy. Tap it to jump to that session’s VS Code window with the cursor in Claude’s input.
  • YOU shows your last prompt; tap to copy all of it.
  • Allow / Deny stay dim until Claude asks for permission, then Allow blinks green. Allow presses 1 and Deny presses Esc in the Claude panel. While Claude is working, Deny becomes Stop and interrupts it.
  • Review, Explain, Write Tests, Fix Build paste a saved prompt into Claude and send it. Select code before tapping Explain and it’s attached as context.
  • Claude (Focus) and New Chat jump to the input or start a fresh conversation.

Try it: with some uncommitted changes, tap Review. The status key flips to Working and back to Done. Then ask Claude to run a command it has to ask about (like npm outdated) and answer it with Allow.

6

Make a smart commit

Tap Commit→VS Code task→stage if needed→Claude Haiku writes it→you edit / confirm→commit (+ push)
  1. Have a folder open in VS Code with changes, then tap Commit (Claude page) or Commit+Push (Git page).
  2. VS Code runs the DUO87: Smart Commit task in that window’s workspace, and the key shows Writing…. If nothing is staged, everything is staged (git add -A); if you staged some files yourself, only those are committed.
  3. Claude writes a message matching your recent commits (Conventional Commits, ticket IDs from the branch name, and a short body only when the change needs one). That takes about 2–4 seconds and costs a fraction of a cent: no tools, no thinking, and your notifier hooks stay quiet.
  4. A dialog shows the message. Edit it if you like, then choose Commit, Commit & Push, or Cancel. Cancel un-stages whatever smart-commit staged.
  5. The key shows the new short hash for two minutes. Commits get Signed-off-by (turn that off with commit.signoff) and are signed however your git config signs commits.

It works from any terminal too:

~/.duo87/bin/smart-commit            # current repo, with the dialog
~/.duo87/bin/smart-commit --dry-run  # just print the message
~/.duo87/bin/smart-commit ~/Sites/app --push --yes

Settings (model, dialog on/off, sign-off, a Co-Authored-By trailer, notifications) are under "commit" in ~/.duo87/config.json. See Config options.

7

Use the VS Code and Git pages

The VS Code page holds the VS Code shortcuts you reach for most: Command Palette, Go to File, Search, Terminal, Go to Definition, Rename, Format, Comment, Sidebar, Split, and Source Control. Each key brings VS Code forward first, so it works even when your browser has focus.

The Git page covers git. Its top row is one wide display instead of three separate keys, so nothing is squeezed into a single tile. It shows the repo, the full branch name, how many files changed, lines added and removed, commits ahead of and behind the remote, how long ago you last committed, and any merge, rebase or conflicts in progress. The branch breaks after / or - so no word is split by the gaps between keys. It follows the repo of the Claude session you prompted most recently (sessions outside a git repo are skipped), SSH and Codespaces included, and refreshes every few seconds.

  • Tap the left third to switch branch, and the rest to open Source Control. Nothing on the display pushes, because VS Code’s Sync pushes without asking when git.confirmSync is off; pushing stays on the Push and Commit+Push keys. To change what a part does, select it in the app and pick Tap.
  • Below it: Commit+Push, Pull, Push, Stash, Undo Commit, GitHub, Create PR and View PR. The PR keys use gh.

Keys that trigger VS Code commands without a default shortcut use combos on F16–F19, which no physical key sends, so they can’t collide with anything. The full list is in F16–F19 bindings.

Add your own: pick an unused combo such as shift+f16, bind it to any command in VS Code’s keybindings.json, then add a Dev Deck Shortcut key that sends it.

8

Customize keys and prompts

There are two ways to change the deck. Pick one per change:

  • In the app (quick tweaks): select a key and edit its fields on the right. To add keys, drag actions from the Dev Deck category in the Function Library: Claude Status, Claude Prompt / Reply, Answer Claude, Focus Claude, Claude Prompt, Smart Commit, Repo Status, Wide Display, Shortcut, Run Command.
  • As code (repeatable, versionable): edit ~/.duo87/profile/layout.json, then reinstall. Each page lists the screen’s rows from top to bottom, three keys per row; null leaves a key empty. ~/.duo87 is a git clone, so commit your layout (or keep it on a fork).
~/.duo87/bin/duo87 install   # rebuild the profile + restart the Play Deck app
~/.duo87/bin/duo87 guide     # refresh this guide from layout.json

Heads-up: duo87 install rewrites the Dev profile’s keys from layout.json, so in-app key edits are replaced. Put changes you want to keep in the file. Your page order, and any pages you add in the app, are kept.

Make any row wide: put two or three Wide Display keys side by side in one screen row and they join into one display. In layout.json that’s a row like [{ "action": "banner" }, { "action": "banner" }, { "action": "banner" }]. In the app, count keys left to right, top to bottom: the app lays the same 12 keys out on its own 4 × 3 grid, but the screen shows them in that same order, three per row. So screen row 1 is keys 1–3, row 2 is keys 4–6, and so on.

Prompt ideas worth a key:

/compact
Summarize what changed on this branch compared to main, as a PR description.
Find the bug in the selected code and fix it. Explain the root cause in one line.
Add logging around the selected code so I can see what it does at runtime.
Refactor the selected code for readability without changing behavior. Run the tests.
9

Optional: program the keyboard itself with VIA

The touch screen is set up in Play Deck; the keys are set up in VIA, and the two don’t affect each other. VIA macros can send the same F16–F19 combos, so physical keys can trigger Smart Commit or focus Claude too.

  1. Download the DUO87 JSON from womierkeyboard.com/pages/softwares.
  2. Open usevia.app in Chrome or Edge (it needs WebHID; Safari won’t work).
  3. Settings → turn on Show Design tab. Design → load the DUO87 JSON.
  4. Configure → Authorize device and pick the DUO87.
  5. Macros tab: paste the macros below into M0, M1, and so on.
  6. Keymap → Layer 1 (the Fn layer): assign the macros to free keys, for example Fn+C for Smart Commit and Fn+K for Focus Claude.
MacroPaste thisDoes
M0{KC_LCTL,KC_LALT,KC_F18}Smart Commit
M1{KC_LCTL,KC_LALT,KC_F19}Smart Commit + Push
M2{KC_LCTL,KC_LALT,KC_F16}Focus Claude input
M3{KC_LCTL,KC_LALT,KC_F17}New Claude chat
M4git status{KC_ENT}Types and runs git status in a focused terminal

Don’t overwrite built-in Fn combos: Fn with F1–F12, Space, Enter, the arrows, Right Shift, Right Ctrl, App, Win, Caps Lock, W, Z and X already do something on this board. Assign macros to keys that show as empty on layer 1.

Screensaver: in the Play Deck app’s Screensaver mode you can upload a 320×480 JPG, PNG or GIF to loop while idle.

10

Use it over Remote-SSH and Codespaces

In a remote window, VS Code runs Claude Code on the remote machine, along with its hooks and git. The deck still presses keys in your local VS Code window, so anything that’s just a shortcut works as-is. The live keys need two pieces: the bridge on your Mac (installed by duo87 install) and the remote kit on each machine you use Claude on.

KeysOn your MacSSH / Codespaces
VS Code page, git keys, prompts, Focus, New ChatWorksWorks, no setup
Claude status, last prompt, Allow / DenyWorksWith the remote kit. The status header reads SSH or CODESPACE, and tapping it focuses that remote window.
Repo status and the wide git displayLiveWith the kit: refreshed after each Claude step and each Smart Commit
Smart CommitmacOS dialogWith the kit: confirm in the task terminal (Enter / p / e / n). It uses the Claude CLI bundled with the remote Claude extension, so sign in there once.
Create / View PR, GitHubghNeeds gh on the remote. Codespaces already has it.
  1. SSH hosts: for each host you run Claude on, install the kit over your normal SSH config (the same one VS Code uses): 
    ~/.duo87/bin/duo87 remote dev-box                 # a Host from ~/.ssh/config
~/.duo87/bin/duo87 remote staging.example.com --dry-run   # show what it would do
    It only writes ~/.duo87 and adds one hook to ~/.claude/settings.json (backed up on the host). Host names containing “PROD” are refused unless you add --force.
  2. A running codespace: gh codespace list, then ~/.duo87/bin/duo87 codespace <name>.
  3. Every new codespace: export the kit into your dotfiles repo, and turn on dotfiles in GitHub → Settings → Codespaces: 
    ~/.duo87/bin/duo87 kit ~/path/to/dotfiles/duo87
# then add to the dotfiles repo's install.sh:
sh "$(dirname "$0")/duo87/install.sh"
  4. Reload any remote window that was already open, then send Claude a prompt there. The status key should switch to the SSH or CODESPACE heading.
  5. After updating the deck, run the same duo87 remote command again on hosts that already have the kit. It’s safe to repeat, and it brings their git snapshots up to the full wide display (lines changed, last commit, staged files, rebases). Older kits still show branch, changes and ahead/behind.

Shared logins: on hosts where the whole team signs in as one SSH user (common on Kinsta and SiteGround), that user’s ~/.claude/settings.json is shared, so everyone using Claude there gets the hook too. It only writes status files; they’re private to that user (mode 600).

Not covered: Codespaces opened in a browser tab (the deck drives the VS Code app), Claude run in a plain ssh terminal outside VS Code, and commits made on a remote, which use that machine’s git identity and signing setup.

Troubleshooting

Keys are blank or black

The keys are drawn as SVG, which the Play Deck app supports. If your firmware or app version shows them blank, switch to PNG mode: add "deck": { "imageFormat": "png" } to ~/.duo87/config.json, then quit and reopen the Play Deck app. Keys stop animating in PNG mode but show the same information.

Tapping a key does nothing, or it flashes a warning

Run ~/.duo87/bin/duo87 doctor. A warning flash usually means Accessibility was turned off for DUO87_Play_Deck, or the key has nothing to do (for example Allow with no pending request). Failed keys are logged in ~/.duo87/logs/plugin.log.

A “1” ended up in my file instead of approving

The approve keys send 1 only after focusing Claude, and only while the status key shows Approve?. If the Claude sidebar was closed, open it once (tap the Claude key), then try again.

Smart Commit didn’t start

The task runs in the frontmost VS Code window and needs a folder open. Run it by hand to see the error: Command Palette → Tasks: Run Task → DUO87: Smart Commit. If signing fails, check that your SSH signing key is loaded (ssh-add -l).

The wide display looks split, or its parts are out of order

Its keys have to sit side by side in the same screen row. In the app, count keys left to right, top to bottom, three per screen row. The plugin logs where each part sits (wide display key lines in ~/.duo87/logs/plugin.log). If it shows the wrong repo, set Repo path on its left key.

The status key is stuck on Working

A session that crashes never reports that it ended. Stale sessions drop off after two hours; duo87 status lists what the deck sees.

A remote session doesn’t show on the deck

In that remote window, run DUO87 Dev Deck: Show Bridge Status from the Command Palette. If it says there’s no ~/.duo87/state, install the kit there (duo87 remote or duo87 codespace). If the remote keeps home somewhere unusual, set duo87.remoteStateDir in VS Code settings to its ~/.duo87/state path.

Smart Commit fails in a remote window

“No such file” means the kit isn’t installed on that machine yet. “Claude could not write the message” means the remote Claude CLI isn’t signed in: run claude once in a terminal there. Without Claude you still get a basic message you can edit.

After a Play Deck app update, keys went back to defaults

Run ~/.duo87/bin/duo87 install. It re-copies the plugin and profile and makes Dev Deck active again.

Remove everything
  1. In the Play Deck app, delete the Dev Deck profile, then quit the app and remove the com.duo87.devdeck.sdPlugin folder from its plugins directory.
  2. In Claude Code, open /hooks and remove the claude-status-hook.js entries (or restore settings.json from ~/.duo87/backups/).
  3. Delete the DUO87 entries from VS Code’s user keybindings.json and tasks.json, and run code --uninstall-extension duo87.devdeck-bridge.
  4. On each remote where you installed the kit, remove the claude-status-hook.js entries from ~/.claude/settings.json (a .duo87-backup-* copy sits next to it) and delete ~/.duo87.
  5. Delete ~/.duo87 (the clone, with its backups and state).
